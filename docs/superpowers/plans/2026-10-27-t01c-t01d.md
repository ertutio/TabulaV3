# T01c/T01d 副本证据账本与清理闭环 实施计划

> **历史设计参考：** 本文保留当时的拆分方案；实现/续接以[持续开发总计划](../../../.ua/DEVELOPMENT_ROADMAP.md)、[当前进度](../../../.ua/DEVELOPMENT_PROGRESS.md)和[验收约定](../../acceptance.md)为准。先核对已交付子项，旧复选框与历史失败记录不代表当前状态；完成本文片段后返回总任务执行循环。

**Goal:** 在 t01 分支（T01a 止损 + T01b 复制事务已完成）基础上，建立 source→verified destination 的原子证据账本（T01c），并恢复"清理前重新校验目标"的清理闭环与归档提交的原子领取/失败反馈（T01d）。

**Architecture:** MediaStore 复制事务已经算出源/目标 SHA-256，但被丢弃——第一步让它把证据带出来。新增 `CopyEvidenceStore`（AtomicFile + Mutex，仿 RecycleBinManager 的 PR #5 模式）按源 URI 持久化"最近一次验证过的目标副本"。归档提交成功后写账本；清理候选 = 有账本条目且目标当前仍存在且身份独立（轻量查询）；删除前的确认时刻再做逐字节深度复核（`verifyCopyIntegrity`）。旧 source_images.json 保持原样，无账本条目的源一律按"未验证"保留。

**Tech Stack:** Kotlin / Coroutines / android.util.AtomicFile / org.json / Robolectric 4.12.2 + JUnit4（自定义 ContentProvider Fake）。

**Spec:** ertutio/TabulaV3 PR #9 正文 T01c/T01d 小节 + TC56/TC57（本仓库 `docs/` 与 PR #9）；约束沿用其"阶段交付与共用约束"。

- MainActivity、AlbumManager、SystemAlbumSyncManager 本会话单人串行写入。
- T01c 完成前不开放清理（Task 3 结束时 `getCleanableUris*` 仍返回空）；Task 4 起分步恢复。

- 提交信息用英文 conventional 风格，与 t01 分支现状一致。

## Review Focus

1. **同名同大小不同内容**：目标被替换成同长度异内容文件时，清理必须拒绝删源——由 Task 5 深度复核测试钉死（`destinationWithSameSizeButDifferentContentIsRejected`）。
2. **账本读失败被当成"全部已验证"**：读账本任何异常必须按"无证据=未验证"处理，绝不能反向——Task 2/4 测试钉死。
3. **并发双提交同一 action**：`commitPendingArchive` 必须原子领取，两次并发只允许一次复制副作用——Task 3 测试钉死。
4. **复制成功但账本写失败**：归档仍算成功（复制副作用已发生），但源必须落入"未验证"，永不可清理——Task 3 测试钉死。
5. **取消传播**：深度复核/轻量校验中的 `ensureActive` 与 `CancellationException` 必须继续向上抛，不得吞成"未验证"后继续删源——Task 5 测试钉死。

### Task 2: CopyEvidenceStore 原子账本

**Files:**
- Create: `app/src/main/java/com/tabula/v3/data/repository/CopyEvidenceStore.kt`
- Test: `app/src/test/java/com/tabula/v3/data/repository/CopyEvidenceStoreTest.kt`

**Interfaces:**
- Produces:
  ```kotlin
  data class CopyEvidenceEntry(destinationUri: String, byteCount: Long, sha256Hex: String, albumId: String, recordedAt: Long)
  class CopyEvidenceStore(storage: EvidenceStorage) { constructor(context: Context)
      suspend fun get(sourceUri: String): CopyEvidenceEntry?   // 读失败 → null（保守）
      suspend fun put(sourceUri: String, entry: CopyEvidenceEntry): Boolean  // 写失败 → false，不抛
      suspend fun removeAll(sourceUris: Set<String>); suspend fun removeForAlbum(albumId: String)
      suspend fun loadAll(): Map<String, CopyEvidenceEntry>    // 读失败 → emptyMap（保守）
  }
  ```
  存储文件 `context.filesDir/copy_evidence.json`，JSON `{"version":1,"entries":{...}}`；写入走 `android.util.AtomicFile`（startWrite→sync→finishWrite，失败 failWrite），写后回读比对（仿 `AtomicRecycleBinStorage`）；所有挂起操作共享 `Mutex`。

- [x] **Step 1: 写失败测试**：roundtrip（put→get 字段一致）；corrupt JSON（写垃圾字节）→ `loadAll()` 空、`get()` null、不抛；`put` 写失败注入（`writeBytes` 抛 IOException）→ 返回 false 且原内容不损；AtomicFile 备份恢复（删 base 留 `.bak`）→ 读到上一版内容；`removeAll`/`removeForAlbum` 生效且空集 no-op。
- [x] **Step 2: 跑测试确认失败**（类未定义）。
- [x] **Step 3: 实现** `CopyEvidenceStore`（含内部 `EvidenceStorage` 接口便于注入故障，镜像 RecycleBinManager 的 internal storage 模式）。
- [x] **Step 4: 跑测试全绿**。
- [x] **Step 5: Commit** `feat: add atomic copy-evidence ledger`

- [x] **Step 1: 写失败测试**：

- [x] **Step 2: 跑测试确认失败**（双提交现有实现会产生 2 次 insert；COMMITTED 枚举未定义）。
- [x] **Step 3: 实现** claim + outcome + 账本写入（`commitPendingArchive` 内 `ensureActive` 语义保持，取消时 action 已领取不回队——与现状一致）。
