# TabulaV3 持续开发总任务

## 任务契约与启动指令

**总目标：** 在保持照片安全、旧数据兼容和现有交互的前提下，完成原 T01–T13 路线剩余实现与验收。下列 C0–C7 是同一个总任务的保存和评审检查点；一个检查点结束后，继续处理下一项就绪工作。

给智谱实现代理的启动指令可直接使用：

> 请读取 AGENTS.md、.ua/DEVELOPMENT_ROADMAP.md 和 .ua/DEVELOPMENT_PROGRESS.md，连续执行这一个总任务。先核对实际分支、源码和已有证据，再从进度文件的 next_action 开始。每个检查点保存进度和提交可评审 PR，然后立即返回执行循环，直到满足总完成条件，或所有就绪工作都被真实外部条件阻塞。保持照片安全约束，按 docs/acceptance.md 验收；不要把一个模块完成、开出 PR 或一次构建成功作为整个任务结束。

启动这项实现工作时，确认当前用户授权是否包括提交分支、开 PR 和运行 CI；只缺某项远端权限时，继续可独立进行的本地实现和验证。合并、签名发布、付费服务及新外发接收方另按实际授权处理。本计划 PR 本身仅修改文档，不代表已启动所有实现或云端工作。

本计划取代 [旧路线图 #9](https://github.com/ertutio/TabulaV3/pull/9) 中“每轮一个子任务，完成后停止，等用户点下一项”的执行方式，保留其 T01–T13、TC01–TC58 和 B01/B02 的产品目标。旧分析的固定版本为 `5948a448cc9cf258fc76ab56b8a86727e2cbbd10`，属于历史证据，不把旧源码行号或旧 NOT_RUN/checkbox 当成当前事实。当前基线和实际完成部分只维护在[进度文件](DEVELOPMENT_PROGRESS.md)。

## 每次进入或恢复时

1. 读取进度文件中的总状态、当前检查点、next_action、阻塞及未完成 PR；核对远端 master、工作分支、工作区和运行中的 CI。保存未提交改动，保留其他执行者的文件所有权。
2. 将记录的 SHA 与实际源码核对。只复用输入、工具链、环境和目标断言仍适用的证据；分支移动或旧记录未落盘时先确认真实状态，避免重复提交、重复运行或覆盖工作。
3. 找到最早一项依赖满足的未完成工作，记录本次具体通过条件，再读取该路径需要的源码、调用者、持久化和失败处理。旧索引用于定位，不作为当前行为的替代证据。
4. 实际环境无法调用某技能、子代理、模型或工具时，使用已验证的可用接口；记录缺口。外部平台的额度或会话硬中断不能由文档解除，恢复时仍从落盘记录核对后继续。

## 持续执行循环

每完成一个可保存单元，都在**同一执行任务中**完成以下循环：

1. **选择：** 从 C0–C7 中选择依赖已满足且无真实阻塞的工作。检查点可以继续拆成一个行为边界的提交，不把范围扩大成整库重构。
2. **实现：** 先复现或建立能区分旧行为的回归证据，做最小实现，接通调用者、UI、持久恢复和失败路径。纯文档或低影响可逆改动用适当静态检查，不机械制造测试。
3. **验证：** 按[验收约定](../docs/acceptance.md)运行受影响检查；行为边界稳定后做必要集成。失败先区分产品、夹具、工具输入及平台环境，不靠取消断言、吞异常或增加权限换取绿色。
4. **保存：** 更新进度、证据和一条可执行的 next_action，提交可恢复的代码。适合评审的行为边界开 PR，写明范围、实际测试、未测项、依赖 PR 和剩余工作。
5. **继续：** 检查是否达到总完成条件；否则立即选择下一就绪项并继续实现。阶段小结用于记录，不以“本阶段已完成，是否继续”结束整个任务。

PR 等待评审时，先做无依赖工作。需要基于未合并改动继续时，可建立有明确父 PR 的后续分支和堆叠 PR，记录 base/ref/SHA，避免重复引入其他人的改动；共享契约未定或存在冲突时只暂停受影响路径。父 PR 合并后再按实际基准调整后续 PR，并重验受到变基影响的范围。没有管理堆叠 PR 的可用工具时，可在同一工作分支以独立提交保存，记录待拆分 PR；不为开 PR 绕过权限或自行合并。

## 总完成、暂停和故障升级

**总任务完成**同时要求：

- C0–C7 中属于当前授权范围的交付均有实现或经用户明确接受的范围调整；T01–T13 每组的剩余项都有结论，没有仅靠旧复选框标完成。
- 相关 TC 的全部要求有对应断言和有效证据；必要设备/迁移/故障恢复检查没有用单测、构建、缓存命中或自有媒体探针替代。
- 所有改动可追溯到提交、PR 和实际测试 SHA；遗留失败已解决或由用户明确决定处理方式，没有未保存的变更或状态不明的副作用。
- 已汇总最终交付范围、回退方式和验收结果。尚待人工评审/合并或真实设备的交付，标为 `awaiting_human`，不能称为最终完成；发布是否执行取决于另外的发布授权。

只有以下条件允许结束当前执行回合：用户要求暂停/改变范围；宿主额度、上下文或工具强制中断；存在真实权限、凭据、设备、产品决策或未定接口阻塞，且已完成所有独立可做的就绪工作；或已满足总完成条件。保存 `next_action`、准确阻塞和恢复条件后报告。缺工具、离线或被平台强制结束是可恢复状态，不伪称完成，也不自动无限重试。

同一卡点保留目标、假设、修改、验证和累计失败次数。两次针对性修正及有效验证仍不通过，或下一步将改变关键安全机制而证据不足时，先寻求独立只读判断；环境无该能力时保留现场并报告。采纳建议后的定向修正仍失败，等待用户针对该卡点决定，同时继续其他独立工作。权限/工具输入无法形成有效验证时记“待验证”，不把换任务名当新重试额度。

## 检查点与依赖

默认主线为 **C0 → C1 → C2 → C4 → C5 → C6 → C7**；C3 在版本/身份契约明确后可独立，C5 的工具验证也可提前。每个检查点均包含适用的 T13 验证，不必等远期优化才交付安全修复。

### C0 安全与一致性的当前差额：T01、T02、T05、T11a

目标：保留已经交付的复制证据、快照投影、恢复核验、详情完整模型、Bitmap 所有权和可信特征缓存，补齐组级安全与错误路径证据。

- 从进度文件的已交付表开始，对照 TC01–TC12、TC23–TC26、TC48–TC50 中的相关语义、TC56/TC57；建立“已覆盖断言/缺失断言”差额，不重写已有函数。
- 先复现图集首次加载失败、空列表下错误与重试是否可见；需要修复时覆盖首次错误、重试成功、切图集/取消后旧结果不覆盖新页面。
- 对 API37 创建空相册的旧路径观察做合成数据最小复现及必要基线对照，确认问题类型后局部修复。它目前不是已证实的本 PR 新增回归。
- 检查复制/移动回退失败及取消、action 并发/撤销、恢复 UNKNOWN/缺失、JSON 兼容、部分失败/重建等完整要求；已有有效测试可复用，缺少的才补。

退出条件：已有实现没有安全回退，缺失行为已修复并有相应证据；未取得的真实多卷/断电/真机证据逐条留在阻塞或待验证栏。设备尚不可得时，继续不依赖该设备证据的 C1/C3/工具准备，不能据此宣布 C0 或总任务完成。

### C1 完成身份消费者与旧索引迁移：T03

依赖：已交付 MediaItemKey 和 bucket 复合分组契约；每簇迁移前确认读写者及兼容路径。

- 建立消费者清单：Album/图集元数据、AlbumUsageTracker、AppPreferences 冷却与专清、ImageHashCache、RecommendationEngine、StorageStatsManager 和 UI 选择/持久进度。
- 每次迁移一簇，以具体卷、媒体项/URI 和内容版本区分真实身份；显示名仅展示，按名合并是显式产品行为，不能代替身份。
- 冲突旧键保留待解析；兼容读取、重复执行幂等、写入失败及进程中断后恢复；保留无关冷却与整理进度。

退出条件：消费者逐项记录迁移或有依据的失效策略；TC13–TC16、TC58 对应的同名跨路径/卷、编辑与可读性恢复、旧数据迁移断言全部有证据。基础键存在不代表 T03 全组完成。

### C2 删除入口统一及 UNKNOWN 隔离：T04

依赖：C0 的删源安全约束、C1 中受影响的身份契约；可先准备不依赖迁移的接口与测试。

- 枚举原图清理、回收站和详情等实际删除入口，以现有串行 `deleteInBatches` 为起点，逐入口接入按项结果和记录适配器。
- 验证 2001 项分批、部分成功、取消后不请求后续批次、授权拒绝、服务错误分类；仅无效请求可按既定规则拆分。
- UNKNOWN 按任务/媒体隔离，保留记录但不阻断无关照片；持久日志失败、重启和授权恢复不重复删除，不把整体 Boolean 当作每项结果。

退出条件：TC17–TC22 的批次、取消、恢复和隔离要求均可追溯到真实调用链；各入口使用同一结果约定且没有扩大用户确认的删除集合。

### C3 预加载请求与生命周期：T06 剩余部分

依赖：T06a 所有权已交付；请求版本与 C1 契约对齐，无需等待整个 C2。

- 保留两种 CardStack 的借用/自有 Bitmap 边界；请求键含 URI、版本和选项。

- 动画完成、对象替换、取消、页面退出和恢复均保持正确所有权；显示质量、HDR/实况及手势保持。

退出条件：TC27–TC31 的归属、请求与生命周期断言通过，旧请求不回写新批次；不以新增缓存掩盖取消/释放错误。

### C4 前台媒体同步和真实移动结果：T07

依赖：C1 身份、C2 删除/授权结果、C0 安全约束；共享接口稳定后按刷新、缓存和移动子边界分别提交。

- 覆盖权限 NONE/PARTIAL/FULL 变化及部分集合 A→B、全量→部分、外部拍照/编辑/移动/删除，只提交较新快照，保护当前交互批次。
- 统一推荐/专清/哈希的版本失效，临时不可读恢复后按有界策略重算；先明确小组件计数口径。
- 移动逐项返回 Moved/CopiedButSourceRetained/NeedsPermission/Failed 等等价明确结果；系统授权拒绝、源删除失败或目标未验证均保留源并如实反馈。

退出条件：TC32–TC35、TC56、TC58 覆盖权限转换、快照竞争、内容变化与移动授权；实际 UI、缓存和持久进度采用相同结果。

## 全程保持的约束

- 唯一完整副本安全优先。PRESENT/MISSING/UNKNOWN 分开；没有独立完整目标及当前证据，保留源和待确认记录。用户确认集合固定，深度复核只缩减，不纳入之后新增候选。
- 保留已有 AtomicFile、互斥、意图日志、授权恢复和 recentVolumes 减 mountedVolumes 的语义；未知不是缺失，取消不能吞成普通失败。
- 保留 `com.tabula.v3`、fork 签名、旧照片与记录、原作者来源/鸣谢、分享、HDR/实况、两种卡片样式与手势；处理保持本地确定性，不引入运行时模型推理。
- 删除、移动和故障注入只使用有清单的自建合成媒体，精确清理并验证集合外哨兵；测试收尾 shell 能力只用于夹具，不给生产应用提权，不替代他人照片的真实授权验证。
- 一个文件只有一个写入者；MainActivity、AlbumManager、SystemAlbumSyncManager 和版本配置的接入协调进行。复用已有机制，缺口有证据才引入新层或依赖。
- 暂缓方向维持原范围：整包 R8 keep 收紧、ART Baseline Profiles、大图库分页/索引、Compose/Coil 大版本迁移及未使用 Media3，不随本总任务自动扩入。
