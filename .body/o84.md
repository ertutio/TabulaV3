对应路线图 #83 第 1 项：**先清已经堆起来的截图和下载图**。

## 用户从哪里进入，改完能做什么

两个入口：

- 设置 → 浏览体验 → **暂存清理**（首项）
- 主界面顶部栏 → 图库按钮

进入后分两步：

1. **选来源**。首次进入列出设备上的截图目录、下载目录，预勾前 3 个。来源身份是「卷 + 相对路径」，跨卷同名目录不合并。
2. **看候选**。按**存入日期**分组列出：超过 7 天的默认展开（建议清理），最近 7 天与"存入时间未知"分列，未知项默认不勾、要求逐张确认。

勾选后有两个出口，语义严格分开：

- **「移入回收站」** → 走现有回收站，可在回收站恢复。本 PR 不删除文件、不调 MediaStore 删除。
- **「长期保留这 N 张（以后不再提示）」** → 写入偏好，跨重启生效，且只影响暂存清理范围；卡片整理与图集里这些照片原样可见。
- 「这次先不看」 → 只压住当前进程内的候选，重启后照片重新出现。

## 关键实现与审计入口

**照片身份（重点）**

- 保留 / 跳过 / 已回收三个集合一律用 `卷|ID` 身份键（`data/cleanup/StagedCleanupRules.kt` 的 `cleanupIdentityKey`，与既有 `mediaIdentityKey` 同口径），不用裸 ID。跨卷同数值 ID 是不同照片，单测 `sameNumericIdOnAnotherVolumeIsNotTheSamePhoto` 钉住。
- 已进回收站的照片从候选里扣除，不会重复入站。
- 来源身份沿用 T03 契约：`(volumeName, relativePath)`，显示名只用于文案。

**时间语义（重点）**

- `ImageFile` 新增 `dateAdded`（`MediaStore.DATE_ADDED` 秒 × 1000，`0` = 未知）。四个查询路径统一携带该列：`getAllImages` / `queryImages` / `queryImagesWithBundle` / `loadAllData`，经 `cursorDateAddedMillis` 换算。
- **未知不猜**：列缺失、NULL、非正值一律 0，绝不当作 1970 参与门限比较——否则所有未知项都会显示成"很久以前"。
- 门限用**自然日**（今天 00:00 − 7 天），不是 `now − 7×24h`。用户理解的"七天前"是日历上的七天，时区和夏令时会改变 `7×24h` 的实际含义。单测 `retentionCutoffIsMidnightBasedNotHourBased` 覆盖。

**权限与回收站**

- 只读 MediaStore（`RELATIVE_PATH` / `VOLUME_NAME` / `DATE_ADDED` 均为既有查询已用的列，**不新增任何权限**）。
- 写回收站走 `RecycleBinManager.addAllToRecycleBin`，与卡片上滑删除**完全同一条路径**，因此回收站恢复、删除确认、权限流程全部复用，没有第二套删除逻辑。

**跳过 vs 长期保留（必须分开，否则是产品缺陷）**

| | 存储 | 生效范围 | 重启后 |
|---|---|---|---|
| 这次先不看 | 进程内字段 | 当前候选 | 照片**回来** |
| 长期保留 | `SharedPreferences` | 暂存清理范围 | 照片**仍不出现** |

两者混淆会出现两种后果：跳过变永久（用户以为只是这次）、或保留失效（用户以为已永久排除）。`StagedCleanupPreferencesTest` 用新建实例模拟重启，逐条钉住：
- `retainedKeysSurviveANewPreferencesInstance`
- `skippedKeysAreDeliberatelyProcessLocal`
- `retentionCanBeReleased`
- `emptySourceSelectionIsDistinctFromNeverChosen`（清空来源 ≠ 从未选过，否则界面卡在来源页出不去）

**规则层是纯逻辑**：`data/cleanup/StagedCleanupRules.kt` 只依赖 `ImageFile` 与 `java.util.Calendar`，能被 JVM 单测逐条钉住，也便于第 2 项复用同一套身份与时间口径。

## 人工验收路径（可复现）

前置：Android 13+ 设备，相册里有 3 张 8 天以上的截图（`DCIM/Screenshots/`）和 1 张 2 天内的截图。

1. 安装 `app-debug.apk`，授权照片访问。
2. 设置 → 浏览体验 → 暂存清理。**预期**：出现来源列表，截图目录被预勾，显示张数与路径。
3. 点「查看 N 个来源的旧图」。**预期**：超过 7 天的分组在前，2 天内那张在「最近 7 天」里，两者分开。
4. 勾选全部旧截图 → 「移入回收站」。**预期**：Toast 报张数；返回卡片页这些截图不再出现；回收站里能看到。
5. 在回收站恢复其中一张 → 回到暂存清理。**预期**：这张**重新出现在候选里**（已离开回收站，且仍超过 7 天）。断言点：恢复不等于永久排除。
6. 勾选一张 → 「长期保留这 1 张」→ 杀掉进程重开 → 进暂存清理。**预期**：这张**不再出现**。
7. 勾选另一张 → 「这次先不看」→ 确认它立刻消失；杀进程重开 → **预期**：它**又出现了**。
8. 换一台有两个存储卷的设备（或 SD 卡），确认同名 `Screenshots` 目录在来源列表里是**两条**，勾选其一不会带走另一卷的照片。
