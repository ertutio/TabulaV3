## 4. #84 的卡点：完整证据链

### 现象

`fullPageFlowThroughHardRestart` 在 `hardRestart()` 之后的 `startApp()` 超时：

```
waitFor timeout: 回收站 （屏幕：[Tabula Logo, 没有找到照片, 请确保已授权访问相册]）
```

### 已排除的假设（都实测过，别重走）

| 尝试 | 提交 | 结果 |
|---|---|---|
| `am force-stop ${ctx.packageName}` | `cc2f742` | **无任何输出直接结束**——instrumentation 与被测 APK 同包（`com.tabula.v3.recyclebin.test`），force-stop 杀掉测试进程自己 |
| `am kill` + 重启 | `2c6b03f` | 重启后显示"没有找到照片" |
| `am kill` + 重新 `grantMedia()` + 重启 | `2c6b03f` | 同样失败（run 45186394357） |
| 仅 `finish()` + 冷启动 Activity | `8b1264f` | 仍失败（run 45189271436）——**这是最新状态** |

### 关键事实

- 重启**之前**的步骤全部通过：进入设置 → 暂存清理 → 来源选择 →
  「查看 1 个来源的旧图」→ 候选页显示「超过 7 天（建议清理）· 1 张 ·
  sc-xxxx.jpg」→ 坐标点击勾选 → 点「移入回收站（1 张）」→ 回收站记录增加。
- 失败**只在重启之后**。
- `finish()` 后重新 `startActivitySync` 仍报"没有找到照片"，
  说明不是权限问题，而是 **MediaStore 查询在新 Activity 里返回空**——
  可能是 `LocalImageRepository` 的缓存/单例在 finish 后状态不一致。

### 三条可选出路（按推荐度排序）

**A. 降低这条用例的重启强度，并如实标注（最省事，也最诚实）**

把"重启后验证"改成两个独立可断言的事实：
1. `RecycleBinManager` 的持久化数据跨 Activity 重建仍在（已有
   `recycleBinSurvivesHardRestartWithRealProcessKill` 可覆盖）；
2. 暂存页状态由持久化数据重建（`hasStagedCleanupSourceChoice` /
   `stagedCleanupSourceKeys` 跨 Activity 保持）。

然后在 PR 正文把「真机冷启动」明确列为**未运行**。
理由：同进程 instrumentation 无法真正冷启动，硬凑出来的"通过"是假的。

**B. 先排查 `LocalImageRepository` 在 Activity 重建后的行为**

`finish()` 后新建 Activity，`loadAllData()` 返回空。可能是：
- 单例持有的 `Context` 是已销毁 Activity 的 context；
- 或 MediaStore 查询依赖某个只初始化一次的注册。

这条路能真正修掉一个潜在产品 bug（Activity 重建后图库为空是严重问题），
但要先写一个最小复现：`finish()` → 新建 Activity → 看 `loadAllData()` 是否为空。

**C. 拆成两个 instrument 进程**

在 workflow 里跑两次 `am instrument`：
第一次执行"移入回收站"，第二次（新进程）执行"恢复 + 断言状态"。
跨进程即真重启。需要把夹具（照片 URI）通过文件传给第二次运行。
成本最高但最接近真实。

### 下一步建议

先花 10 分钟验证 **B 是否成立**（写个最小用例：finish → 新建 → loadAllData 是否空）。
- 若成立 → 这是产品 bug，修 `LocalImageRepository`，然后 A/B 一起解决；
- 若不成立 → 走 A，把真机冷启动列为未运行，PR 正文写清楚。

### 模拟器 workflow 的坑（都踩过）

- runner 用 `/bin/sh` 且**按行逐条执行**：不能用续行、不能 `{ }` 多行块、
  没有 `pipefail`
- `set -eux` 会让失败提前终止——诊断命令要放在断言**之前**
- 断言必须**精确条数**（`grep -Fx 'OK (6 tests)'`），不接受任意 `OK (N tests)`
- 每个测试类**分开运行、分开保存输出**
- Maven Central 对 CI runner 返回 **429**，`android-all` 预取已改多镜像且不阻断构建

### 诊断手段（已验证可用）

在测试里 `ins.sendStatus(2, bundle)` 把文本写进 instrumentation status，
日志里搜 `roundintent.diag=` 可见（`println` 会被吞）。
`Log.e` 多行会被截断。
