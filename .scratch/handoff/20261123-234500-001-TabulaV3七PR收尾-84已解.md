## 0. 一分钟读懂

**#84 的卡点已彻底解决，七个 PR 现在全部 OPEN / MERGEABLE，CI 全绿。**

卡点的真实原因**不是**上一份交接猜测的三条（进程重启 / MediaStore 未就绪 /
单例缓存），而是**产品缺陷**：

> 图库为空时，`DeckScreen.EmptyState` **没有顶部栏**，屏幕上只剩 Logo 与
> 「没有找到照片 / 请确保已授权访问相册」。用户把照片全部移入回收站后，
> **回收站入口消失**——而待恢复的照片恰恰在回收站里，等于把自己锁在门外。

`fullPageFlowThroughHardRestart` 正是撞在这里：它把唯一一张照片移入回收站后
重启，`projectSnapshot` 扣除软删除项后图库确实为空 → 进 `EmptyState` →
`waitFor("回收站")` 超时，屏幕内容就是那三行文本。

前七轮把"图库为空"误读成"图库读不到"，才在权限与缓存上绕了七圈。

## 3. 本轮改了什么（三笔提交）

### `166d236` fix(deck): 空图库保留顶部栏，回收站入口不再消失 ← **产品修复**

- `DeckScreen.EmptyState` 接收 `onTrashClick` / `onSettingsClick` /
  `topBarDisplayMode`，内部渲染 `TopBar`，提示文案居中在下方内容区
- `TopBar` 在 `totalCount == 0` 时不再显示 `1/0`，只留回收站与设置

### `d2bfb42` fix(test): 回收站列表页没有「恢复」，必须先点开照片

回收站**列表页没有「恢复」按钮**——「恢复」只在点开照片后的全屏查看器底部
操作栏里。原用例进了列表就直接 `waitFor("恢复")`，必然超时。
现在先确认进列表 → 断言照片在列表 → `tapByBounds` 点开照片 → 再恢复。

### `34b8bb2` fix(test): 等待文案用子串匹配，回收站计数是「1 项待处理」

`waitFor` 是**精确文本相等**，而回收站条目计数是「1 项待处理」这种带数字的
句子，`waitFor("待处理")` 永远等不到。新增 `waitForTextContaining` 做子串匹配。
查看器里的「恢复」是精确文本，**仍用 `waitFor`，没有放宽**。

### 新增用例

`emptyLibraryStillReachesRecycleBinAndRestores`（在 `StagedCleanupPageFlowTest`）：
构造「照片全在回收站、图库为空」的终态，断言空状态与回收站/设置入口**同时存在**，
并真正走完 进回收站 → 点开照片 → 恢复 → 回收站记录减少。

## 4. 别再重走的三条死路（上一份交接的第 4 节）

| 尝试 | 结论 |
|---|---|
| `am force-stop` | 会杀掉同包测试进程自己，确实不可用——**但它不是本失败的原因** |
| `am kill` / 重新 `grantMedia()` | 与失败无关，图库"为空"是真的空，不是读不到 |
| `LocalImageRepository` 单例缓存不一致 | **不存在**。`LocalImageRepository` 每次 new，无单例、无缓存 |

**判据**：屏幕内容里从头到尾没有 MediaStore 或权限的痕迹，只有 `EmptyState`
的完整三行文本。看到那三行，先问"图库是不是真的空"，不要先怀疑权限。

### 本机限制

- **没有模拟器、没有 AVD、没有连接设备**（`adb devices` 为空）。
  所有设备验证只能靠 GitHub Actions 的 `verify-staged-cleanup` workflow。
- 一次 CI 往返约 13 分钟（build 3m + 两个 profile 各 4m）。

### 模拟器 workflow 的坑（都踩过）

- runner 用 `/bin/sh` 且**按行逐条执行**：不能用续行、不能 `{ }` 多行块、没有 `pipefail`
- `set -eux` 会让失败提前终止——诊断命令要放在断言**之前**
- 断言必须**精确条数**（`grep -Fx 'OK (3 tests)'`），不接受任意 `OK (N tests)`
- 每个测试类**分开运行、分开保存输出**
- Maven Central 对 CI runner 返回 **429**，`android-all` 预取已改多镜像且不阻断构建

### 诊断手段

在测试里 `ins.sendStatus(2, bundle)` 把文本写进 instrumentation status，
日志里搜 `roundintent.diag=` 可见（`println` 会被吞）。`Log.e` 多行会被截断。

**本轮最有效的诊断**：失败时 `screenTexts()` 会把整屏文本打进错误消息。
`[Tabula Logo, 没有找到照片, 请确保已授权访问相册]` 这一行就是全部答案。
